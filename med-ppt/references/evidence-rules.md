# 医学证据、数字与图片规则

这些规则在写 brief 时执行，并在交接时作为约束传给 ppt-master。

## 数字

1. 只使用原文或用户资料中的数字。缺失就写"原文未报告"或"资料未提供"，并列入 brief 的"待用户补充"。
2. 效应量（HR、OR、RR、MD 等）连同 95% CI 一起出现；只有 P 值时注明"原文仅报告 P 值"。
3. 相对效应与绝对效应同时可得时，两者都写；派生数字（如 1−HR、NNT）登记为 `derived:`。
4. 检验值带单位、参考范围与检测时间。
5. 数字精度与原文一致，不自行四舍五入。

## 措辞

1. 区分三类表述："原文结论"、"汇报人解读"、"推测/假设"。
2. 观察性研究不写因果；亚组与事后分析写"探索性"。
3. 临床个案报告中区分"客观发现"、"当时判断"、"回顾性分析"；"未查"与"阴性"不混用。
4. 作者、期刊、年份、机构、注册号必须与原文一致；没有就不写，不得编造 Logo 或机构名。
5. 单个病例不写因果与疗效结论："治疗后××由 A 降至 B"可以，"证明有效""首例"不可以（"首例""罕见"需有文献支持）。
6. 病历资料前后矛盾时（日期、数值、诊断名称），不自行取舍，列入"待用户补充"的"资料冲突"。
7. 研究设计、获批身份、抗体亚型、给药途径、指南推荐强度等会改变医学解读的非数字主张，以 `kind: "claim"` 登记到 `facts.json`。

## 引用

引用文献只能来自用户提供的材料，或本次运行中检索到并核实了 PMID/DOI 的文献。每条引用登记为一条事实（`source` 写 PMID 或 DOI）。不得凭记忆写作者、期刊、年份或病例数；无法核实时留"待补充文献"。

## 图片

| 类型 | 处理方式 |
|---|---|
| 原文 Figure、表格截图 | 原图嵌入，保持宽高比，标注原文图号；禁止 AI 重画或"美化"。**放大到撑满所在区域**（原图占比太小是最常见的毛病），在图旁或图下用原生文字写解释：这张图说明什么、该看哪里 |
| 影像、病理、心电图、检验报告截图 | 原图嵌入；病灶指示用叠加的原生箭头/圆圈，不改原图像素 |
| 需要比较的数字（AUC、准确率、样本量、前后对比） | **用原生图表**（ppt-master 的 chart 模板，如柱状图、条形图），数字来自 facts.json；不要只把数字写成一排卡片，也不要用 AI 画图表 |
| 研究流程图、时间轴、鉴别诊断表 | 用原生形状和表格重建，数字来自 facts.json |
| 软件界面、文件、工作流演示（如"数字溯源链"） | 用真实截图，或真实项目文件的原文摘录排成"文件窗口"；**禁止用 AI 生成假截图、假界面** |
| 封面主视觉、章节页、机制/解剖示意、教学比喻（如光谱、导航漫画、方法示意） | 可用 AI 生图；不承载数据；图中不含任何文字，需要的字由版式用原生文本排在图上或图旁；提示词写明"不含任何文字、数字、标签或伪文字" |

一句话分工：**原图负责证据，原生图表负责数字，AI 插画负责比喻，真实摘录负责演示。**

AI 配图提示词写法：主体（器官/细胞/通路/场景）+ 构图 + 风格（与 Style 的 Image Rendering Behavior 一致）+ 配色倾向 + "白色或透明背景，不含任何文字"。临床个案讨论型讨论段的示意图不得暗示最终诊断。

患者信息的去标识化由汇报人自行决定，本 Skill 不做拦截。
